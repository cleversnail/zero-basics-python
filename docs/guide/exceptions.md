## 第 72 讲 · 初识异常：异常的产生与分类

### 本节目标

搞清「异常到底是什么」，看懂报错信息里的**异常类型**和**栈回溯**，认识异常的层次结构。

### 知识要点

**1. 什么是异常**

> **异常（Exception）**：Python 解释器在执行程序的过程中，出现错误时的一种管理机制。它会在错误被监测到的位置被「引发（raise）」。

三条关键性质：

1. 异常是**自动引发**的——你写错代码，解释器替你把它「扔」出来；
2. 引发异常时，**当前代码块会立即中断**，后面的语句不再执行；
3. 异常是一种**特殊对象**，它有自己的类型、自己的信息。

**2. 栈回溯（Traceback）**

> 除 `SystemExit` 外，当异常没有被完全处理时，Python 都会打印**栈回溯信息**：告诉你「哪一行、哪一种错误」。

读报错要**从下往上读**：最后一行是**错误类型 + 原因**（如 `ZeroDivisionError: division by zero`），往上是**出错位置和调用链**。

**3. 异常的分类（层次结构）**

所有异常的根是 `BaseException`。它的下面分为两大类：

| 基类 | 含义 |
| --- | --- |
| `BaseException` | 所有内置异常的基类 |
| `Exception` | 所有**内置的非系统退出类**异常都派生自它，**所有用户自定义异常也应当派生自它** |

再往下还有几个常用的中间基类：

- `ArithmeticError` —— 各种算术类错误的父类（如 `ZeroDivisionError`）
- `LookupError` —— 映射或序列所用「键/索引无效」时引发的父类（如 `IndexError`、`KeyError`）
- `OSError` —— 操作系统相关错误的父类（如 `FileNotFoundError`）

简化的继承树：

```
BaseException
├── SystemExit          （系统退出，不属于 Exception）
├── KeyboardInterrupt   （Ctrl+C 中断，不属于 Exception）
└── Exception
    ├── ArithmeticError ── ZeroDivisionError
    ├── LookupError ─┬──── IndexError
    │                └──── KeyError
    ├── ValueError
    ├── TypeError
    └── OSError ────────── FileNotFoundError
```

> 📌 **小结**：异常是错误自动引发、无法被解释器自动处理的特殊对象；它有层次结构，
> **拿不准要捕获什么时，就用基类 `Exception` 兜底**。

## 第 73 讲 · 异常捕获：出现异常时，如何利用程序进行处理？

### 本节目标

学会用 `try-except` 把「会出错的代码」包起来，并用 `else` / `finally` / 多个 `except` 控制处理流程。

### 知识要点

**1. `try-except` 代码块**

```python
try:
    可能产生异常的代码
except 异常:
    捕获指定异常后运行的代码
```

含义：**试探着执行 `try` 里的代码**；一旦引发 `except` 指定的那种异常，就跳到 `except` 里处理，程序**不会崩**。

**2. `else` 代码块**

```python
try:
    可能产生异常的代码
except 异常:
    捕获后运行的代码
else:
    try 部分没抛出异常，才执行这里的代码
```

`else` 是「一切顺利」时才走的分支，常用来放「只有成功才该做的事」。

**3. `finally` 代码块**

```python
try:
    可能产生异常的代码
except 异常:
    捕获后运行的代码
finally:
    无论是否抛出异常，该部分代码均会执行
```

`finally` 常用来**收尾**：关闭文件、释放连接。即使 `try` 里出了异常、或者被 `return` 提前结束，它依然会执行。

**4. 捕获多个异常**

一个 `try` 可以配多个 `except`，**从上到下依次匹配**：

```python
try:
    可能产生异常的语句
except 异常1:
    处理方式一
except 异常2:
    处理方式二
```

也可以**嵌套**使用：

```python
try:
    try:
        语句
    except:
        pass
except:
    pass
```

> ⚠️ 匹配是**自上而下、先到先得**。如果把父类（如 `Exception`）写在前面，后面的子类 `except` 永远轮不到。
> 所以经验法则：**具体的异常写前面，宽泛的基类写最后**。

### 课后作业

> 在文件操作过程中，使用 `open()` 函数打开文件时，有可能会出现该文件在磁盘中不存在的异常，
> 请编写 `try-except` 语句，对文件打开的异常进行异常捕获。
> \* 当出现异常时，需关闭文件；无异常时正常读取文件。

参考答案（即代码实操的示例 5）：用 `FileNotFoundError` 精确捕获「文件不存在」；把 `f.close()` 放进 `finally`，保证无论成功还是失败、只要文件被打开过就一定关掉。

```python
def read_file(path):
    f = None
    try:
        f = open(path, mode="r", encoding="utf-8")
        return f.readlines()
    except FileNotFoundError as e:
        return f"文件不存在，无法打开：{e.filename}"
    finally:
        if f is not None:
            f.close()
```

## 第 74 讲 · 自定义异常捕获：如何定义业务异常？

### 本节目标

学会定义**自己的异常类**来表达业务规则，并用 `with` 语句简化资源清理。

### 知识要点

**1. 自定义异常的用途**

> 借用 Python 强大的异常处理功能，编写程序**中断逻辑**——继承现有的异常，并为它**增加额外功能**。

一句话：内置异常描述的是「程序层面的错误」（除零、越界）；**业务异常**描述的是「规则层面的错误」
（余额不足、用户名违规、文件太小）。后者能让报错更贴近你的业务。

**2. 自定义异常的方法**

自定义异常需要**继承异常的基类**，一般通过继承 `Exception` 实现：

```python
class MyException(Exception):
    ...

# 主动引发
try:
    raise MyException
except MyException as e:
    print(e)
```

实战里通常会在 `__init__` 里保存业务信息，并用 `super().__init__(...)` 交给父类，这样 `str(e)` 就能打印出原因。

**3. `with` 语句**

> 为了简化异常处理逻辑，Python 引入了 `with` 语句。以打开文件为例：

```python
with open("/path/to/file.txt") as f:
    txt = f.readlines()
```

离开 `with` 代码块时，文件**自动关闭**——不用手写 `close()`，也不用担心忘记关。

`with` 背后靠两个**魔术方法**实现：

| 方法 | 何时调用 | 作用 |
| --- | --- | --- |
| `__enter__()` | 进入 `with` 块时 | 返回值交给 `as` 后面的变量 |
| `__exit__()` | 离开 `with` 块时 | 收尾清理；能拿到块里发生的异常信息 |

自定义 `with` 语句的写法：

```python
class MyClass:
    def __enter__(self):
        ...
    def __exit__(self, exc_type, exc_value, tb):
        ...

with MyClass() as mc:
    mc.xxx()
```

> 📌 **小结**：自定义异常必须继承 `Exception`；它可以用 `raise` 让程序中断；
> `with` 语句能简化异常处理与资源清理。

### 课后作业

> 请编写自定义异常类：如果读取的文件小于 10 个字符，抛出「文件过小」的自定义异常；
> 如果读取的文件大于等于 10 个字符，则正常输出该文件内容。

参考答案（即代码实操的示例 6）：

```python
class FileTooSmallError(Exception):
    """自定义异常：文件内容太少。"""


def read_file(path, min_chars=10):
    with open(path, encoding="utf-8") as f:
        content = f.read()
    if len(content) < min_chars:
        raise FileTooSmallError(f"文件只有 {len(content)} 个字符，少于要求的 {min_chars} 个")
    return content
```

## 第 75 讲 · 避坑指南：编写捕获异常程序时经常出现的问题

### 本节目标

识别并避开编写异常处理代码时的**四类常见错误**：位置、范围、处理方式、嵌套语法。

### 知识要点

**坑 1：捕获位置设置不当**

> 只要在猎物的必经之路上设陷阱，一定可以捕到猎物。

- `try-except` 设得**太晚**，程序已经在前面报错退出了，陷阱白设；
- 受 `if`、`while` 等分支影响，某条路径**根本没执行到** `try-except`。

原则：**陷阱要设在错误发生之前**。

**坑 2：捕获范围设置不当**

- 捕获范围**过大**：一上来就 `except Exception`，抛出异常时无法定位原因；
- 用 `Exception` 基类捕获，**原因不明确**。

原则：**能精确到具体异常类型就别用基类**；基类只放在最后兜底。

> ⚠️ 补充：`except Exception`（甚至裸 `except:`）会吞掉很多你想知道的信息。
> 好在 `KeyboardInterrupt`（Ctrl+C）和 `SystemExit` **不是** `Exception` 的子类，
> 它们会「穿透」普通的 `except Exception`——所以别写裸 `except:`，否则连 Ctrl+C 都按不动。

**坑 3：捕获处理设置不当**

- 捕获后应当**明确告知用户异常原因**，而不是只丢一句「出错了」；
- 能由程序自动处理的要处理干净，比如**关闭文件**，防止数据丢失。

**坑 4：嵌套 `try-except` 语法错误**

- `try` 和 `except`（或 `finally`）必须**成对出现**；
- 嵌套容易漏写，建议用 IDE 的自动缩进与语法检查来避免。

> 📌 **小结**：位置、范围、处理方式用错，是异常处理里最常见的三类错误；
> 处理语句一长就容易出语法错误，让 IDE 帮你检查。

```text
      嵌套时务必保证 try 与 except 成对出现，靠 IDE 的自动缩进/检查来避免语法错误。
```

**② 第四类「语法错误」**——语法错误在**加载阶段**就被解释器拦下，无法用 `try` 在运行时捕获，所以单独放一个文件。完整代码见 `code/75b-nested-syntax-error.py`（**故意写错**），运行：

### 课后作业

> 程序员小派在调试程序时，发现程序偶尔会抛出自定义异常，但是根据异常提示无法定位
> 异常产生的原因和产生异常的具体代码行数。作为小派的搭档，请你对该问题提出有效的代码优化方案。

参考答案（三个抓手）：

1. **携带足够信息**：在自定义异常的 `__init__` 里保存关键参数（如出错的值、行号），并 `super().__init__(消息)`——别只 `pass` 一个空异常。
2. **保留栈回溯**：捕获后**重新引发**用 `raise`（不要吞掉），必要时用 `logging.exception()` 或 `traceback.format_exc()` 把完整栈写进日志，里面有精确到行的调用链。
3. **范围收窄 + 位置前置**：把 `except Exception` 换成具体的自定义异常类型，并把 `try` 挪到错误真正发生的位置，避免「宽泛捕获 + 位置过晚」双双掩盖问题。

## 本章小结

**速查表**

| 主题 | 关键点 |
| --- | --- |
| 异常是什么 | 错误**自动引发**、无法被解释器自动处理的特殊对象；引发时当前代码块**中断** |
| 栈回溯 | 除 `SystemExit` 外，未处理的异常都会打印 Traceback；**从下往上读**（类型 + 位置） |
| 异常层次 | 根是 `BaseException`；自定义异常与绝大多数内置异常都继承 `Exception` |
| 拿不准捕获什么 | 用基类 `Exception` 兜底（但别写裸 `except:`） |
| `try-except` | 接住指定异常，程序不崩 |
| `else` | 只有 `try` **没出错**才执行 |
| `finally` | **无论**是否出错都执行，用于收尾（关文件） |
| 多个 `except` | 自上而下匹配，**具体异常写前、基类写后** |
| 自定义异常 | `class MyException(Exception)`，用 `raise` 引发、`except` 捕获 |
| `with` 语句 | 靠 `__enter__` / `__exit__` 实现，自动清理资源（如自动关文件） |
| 避坑四则 | 位置要早、范围要窄、处理要明、`try/except` 要成对 |

**三句话**

1. 异常不是灾难，是**机制**：它会在出错处自动引发、让代码块中断，并带上「类型 + 位置」的栈回溯。
2. 捕获要**位置准、范围窄、处理明**：`try` 设在错误前，`except` 精确到类型，`finally` 把该关的关掉。
3. 业务错误用**自定义异常**表达（继承 `Exception`），资源清理交给 **`with`**。
