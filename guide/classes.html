第 58 讲 · 编程思想不同会导致怎样的代码差异？ ​

本节目标 ​

看懂「面向过程」和「面向对象」两种编程思想，并理解 Python 里「一切都是对象」这句话的含义。

知识要点 ​

1. 面向过程

  • 以**过程（步骤）**为核心，强调「解决问题的流程」。
  • 写代码时的思路是：先 xxx，再 xxx，然后 xxx。
  • 特点：符合时间顺序，易于理解程序逻辑。
  • 适合流程清晰、规模不大的需求。

2. Python 中的对象

Python 即使写「面向过程」的代码，用到的数据也都是对象：

  • 变量指向的基础数据类型（数字、字符串、列表……）全都是对象；
  • id() 函数返回对象的整数标识（可以理解为对象在内存里的编号）；
  • is 判断两个名字是否指向同一个对象；== 判断两个对象的值是否相等。
比较含义例子
list1 == list2值相等[1,2,3] == [1,2,3] → True
list1 is list2是同一个对象[1,2,3] is [1,2,3] → False

3. 面向对象编程

  • 更关注一个对象的定义：它有什么数据、能做什么动作。
  • 优点是更容易抽象和复用：以列表为例，列表是一类对象，它们都有「添加、删除、切片」等共同能力；你为「列表」这一类增加一个能力，所有列表就都具备了。

4. 两者的区别

  • 面向对象比面向过程更适合复杂度高的编码需求；
  • 面向对象适合封装需求更严格的程序；
  • 面向对象可设计的编程模式更丰富；
  • 面向对象涉及的技术概念更多（后面几讲的类、继承、装饰器就是明证）。

💡 一句话：面向过程盯着「怎么做」，面向对象盯着「谁来负责做」。

第 59 讲 · 类与实例：如何使用面向对象的思想编写程序？ ​

本节目标 ​

学会用 class 定义一个类、用「实例化」造出对象，分清类属性、实例属性和方法的区别。

知识要点 ​

1. 定义一个类

python
class Coffee(object):
    pass  # 类体（放在这里定义属性和方法）
1
2
  • class 是定义类的关键字；
  • Coffee 是类名，一般首字母大写；
  • object 是父类，可以不写，默认就继承自 object；
  • 还可以用 type() 函数动态创建类（一般用于特殊场景）。

2. 类的实例化

python
mocha = Coffee()
1

mocha 就是「用 Coffee 这个类实例化出来的一个对象」。可以把类想成图纸，实例是按图纸造出来的具体一件东西。

3. 类的属性

python
class Coffee():
    water = 0
    milk = 0
1
2
3

写在类里、方法外的变量叫类属性，被这个类的所有实例共享。

4. 类的方法

python
class Coffee(object):
    def add_water(self):
        self.water = 1
1
2
3
  • 定义在类里的函数叫方法；
  • 实例方法的第一个参数固定是 self，代表「当前这个对象」；
  • 用 self.xxx = ... 赋的值是实例属性，只属于调用的那个对象。

⚠️ 要能根据上下文，区分「类的实例化」(Coffee()) 和「函数调用」——前者造对象，后者执行逻辑。

代码实操 ​

完整代码见 code/59-class-instance.py：

python
# 第 59 讲 · 类与实例：如何使用面向对象的思想编写程序？


# class 是定义类的关键字；Coffee 是类名（约定首字母大写）
class Coffee:
    # 类属性：写在类里、方法外，被所有实例「共享」
    water = 0
    milk = 0

    # 实例方法：第一个参数固定是 self，代表「当前这个对象」
    def add_water(self):
        # self.xxx 这样写，产生的是「实例属性」，只属于调用的那个对象
        self.hot_water = 1


print("========== 1. 类的实例化 ==========")
# Coffee() 就是「实例化」：类像一张图纸，实例是按图纸造出来的具体一个
mocha = Coffee()
print("  mocha 的类型        :", type(mocha))
print("  mocha 是 Coffee 实例吗:", isinstance(mocha, Coffee))
print("  注意：类本身也是对象 :", type(Coffee))

print()
print("========== 2. 对象拥有类的属性 ==========")
print("  mocha.water =", mocha.water)
print("  mocha.milk  =", mocha.milk)

print()
print("========== 3. 调用实例方法，产生实例属性 ==========")
mocha.add_water()
print("  mocha.hot_water =", mocha.hot_water)

print()
print("========== 4. 两个实例互不干扰 ==========")
latte = Coffee()
print("  改之前：mocha.water =", mocha.water, " latte.water =", latte.water)
mocha.water = 300  # 只给 mocha 自己挂一个实例属性
print("  改之后：mocha.water =", mocha.water, " latte.water =", latte.water)
print("  类属性的原值没变：Coffee.water =", Coffee.water)

第 60 讲 · 类的继承：如何解决代码重用的问题？ ​

本节目标 ​

理解继承的用途，会用 super() 复用父类方法，并分清多继承与 Mixin。

知识要点 ​

1. 为什么需要继承

继承能让新手快速上手大牛设计的代码。比如你想让自定义的字典「在字典功能之上加点料」，直接继承 UserDict 即可：

python
from collections import UserDict

class my_dict(UserDict):
    pass  # 在继承来的字典功能之上，再添加你自己的功能
1
2
3
4

2. 父类与子类

  • 在继承里，被继承的类叫父类，继承的类叫子类；
  • 子类继承父类的属性和方法；
  • 想「加一点、但不丢掉父类逻辑」时，用 super() 调用父类的同名方法。
python
class Father(object):
    def run(self):
        pass

class Son(Father):
    def run(self):
        super().run()      # 先执行父类的 run
        print("run")       # 再补充自己的行为
1
2
3
4
5
6
7
8

💡 思考一下：如果不用 super()，父类 run 里的代码就完全不执行了——这正是「复用」的关键。

3. 类的多继承

一个类可以同时继承多个父类：

python
class D(B, C):
    pass
1
2

当继承图出现「菱形」（A 被 B、C 继承，D 又同时继承 B、C）时，Python 用 C3 算法按顺序遍历继承图。用 类名.__mro__ 可以查看真实顺序。注意：多重继承会增加复杂度，应当少用。

4. 混入（Mixin）

  • Mixin 是借用多继承语法给现有类加方法的技巧；
  • Mixin 只包含方法、不定义新属性；
  • Mixin 便于重用，但绝不能被单独实例化；
  • 命名习惯在类名后加 Mixin。

比如披萨可以按层数（单层 / 双层）和形状（圆形 / 方形）分别做成 Mixin，再拼出一个披萨类：

python
class 披萨(主要材料, 单层Mixin, 圆形Mixin):
    pass
1

python
# 第 60 讲 · 类的继承：如何解决代码重用的问题？


print("========== 1. 父类与子类，super() 复用父类方法 ==========")


# 被继承的类叫父类，继承的类叫子类
class Father(object):
    def run(self):
        print("  run in father")


class Son(Father):
    def run(self):
        super().run()  # 先执行父类同名方法的内容
        print("  run in son")  # 再补充子类自己的行为


f = Father()
f.run()
print("  ---")
s = Son()
s.run()

print()
print("========== 2. 查看继承顺序：__mro__ ==========")
print("  Son.__mro__ =", Son.__mro__)

print()
print("========== 3. 多继承与 Mixin ==========")
# Mixin（混入）：借用多继承语法，只提供方法、不定义属性，也绝不单独实例化，
# 类名习惯以 Mixin 结尾。用它给现有类「拼装」能力，而不是构造复杂继承树。


class CookMixin:
    def cook(self):
        print("  会做饭")


class DriveMixin:
    def drive(self):
        print("  会开车")


class Person(CookMixin, DriveMixin):
    def __init__(self, name):
        self.name = name

    def hello(self):
        print(f"  我是 {self.name}")


p = Person("小明")
p.hello()
p.cook()
p.drive()
print("  Person.__mro__ =", Person.__mro__)

第 61 讲 · 类的装饰器：如何改变类方法的功能？ ​

本节目标 ​

认识三个类装饰器 classmethod、staticmethod、property，知道它们各自改变方法的调用方式和行为。

知识要点 ​

「类的装饰器」是「类方法的装饰器」的简称：通过装饰器改变方法的调用方式和行为。

1. classmethod

把实例方法变成类方法，用类直接调用：

python
class Klass:
    @classmethod
    def func(cls):
        pass
1
2
3
4

cls 表示当前操作的类（不是实例），可以用 Klass.func() 调用。

2. staticmethod

有些函数「不需要类的任何信息，但又和类相关」，为了维护方便、代码工整，可以放进类里用 @staticmethod 修饰：

python
class Klass():
    @staticmethod
    def func():
        pass
1
2
3
4

staticmethod 修饰的方法既不需要 self，也不需要 cls。

3. property

#
# 一杯咖啡由三种原料调配：水、咖啡液、牛奶。
# 每种原料做成一个 Mixin（只放方法），咖啡类把它们拼装起来。
# 本程序用「固定订单」自动跑完，不需要手工输入。


class WaterMixin:
    def add_water(self, volume, temperature):
        # 水以毫升为单位，并且区分冷热
        return f"水     ：{temperature} 水 {volume} ML"


class CoffeeMixin:
    def add_coffee(self, parts):
        # 咖啡液以「份」为单位
        return f"咖啡液 ：{parts} 份"


class MilkMixin:
    def add_milk(self, volume, temperature):
        # 牛奶以毫升为单位，也区分冷热
        return f"牛奶   ：{temperature} 奶 {volume} ML"


class Coffee(WaterMixin, CoffeeMixin, MilkMixin):

                 coffee=1, milk=-1, milk_temp="hot"):

        self.recipe = []  # 配方：逐条记录加了哪种原料

            self.recipe.append(self.add_water(water, water_temp))
        if coffee > 0:
            self.recipe.append(self.add_coffee(coffee))
        if milk > 0:
            self.recipe.append(self.add_milk(milk, milk_temp))

    def show(self):
        print(f"【{self.name}】")
        for line in self.recipe:
            print("  " + line)
        print(f"  —— 共 {len(self.recipe)} 种原料")

]

    print()

第 63 讲 · 避坑指南：类的常见错误 ​

本节目标 ​

认识类的两类典型错误：语法错误（导致程序异常）和设计错误（导致代码耦合严重、无法拆分）。

知识要点 ​

1. 语法错误：导致使用异常

  • 忘记写 self：实例方法的第一个参数必须是 self，忘了它，调用时就会多传一个参数而报 TypeError。
  • 误用 self 和 cls：classmethod 的第一个参数是 cls，staticmethod 里则既没有 self 也没有 cls；在 staticmethod 里写 self 会报 NameError。

self（当前实例）和 cls（当前类）是初学面向对象时最容易忽略的语法。

2. 设计错误：导致耦合严重，无法拆分

要回答三个问题：哪些对象该抽象成类？哪些功能该做成属性、哪些做成方法？类之间的依赖怎么解决？——用 SOLID 原则来指导。

字母原则一句话理解
S单一职责原则一个类只负责做一件事，越小越好
O开闭原则对扩展开放，对修改关闭
L里氏替换原则子类能无差别替换父类，行为一致
I接口隔离原则接口越小越好；Python 用「鸭子类型」实现接口
D依赖倒置原则高层与低层模块都依赖抽象，而不是互相依赖

⚠️ 下面两个文件都是故意触发错误的，运行时会报错——这正是它们的用途。

三句话

  1. 类和实例是「图纸与产品」：定义用 class，造出来用 类名()，第一个参数 self 不能忘。
  2. 复用靠继承：用 super() 接住父类逻辑，能少用多继承就少用，Mixin 只加方法。
  3. 初始化靠 __init__：实例化时自动执行并接收参数；扩展数据类型时先想魔术方法。
