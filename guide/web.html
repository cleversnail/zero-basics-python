第 99 讲 · 理论盘点：Web 客户端与服务端 ​

本节目标 ​

先不写框架，把「上网」这件事拆成两半：浏览器做什么、服务器做什么； 再用 Python 自带的 http.server 亲手把一个目录发布成网页，获得第一手的「服务端」体验。

知识要点 ​

1. Web 客户端和服务端，各管什么？

角色典型代表主要职责
Web 客户端Chrome、Firefox、Edge 等浏览器解决用户与服务器的交互：把用户的请求提交给服务器；再解释服务器返回的图片、代码，展示给用户
Web 服务端一台跑着 Web 程序的服务器接收客户端请求 → 向上游数据库请求数据 → 经中间件处理 → 以特定形式返回给浏览器

一句话：客户端负责「展示和收集输入」，服务端负责「处理请求、组织数据」。

2. Web 服务端需要处理的主要数据

数据含义
HTTP 协议头又分「请求方式」和「请求内容」两部分
HTTP 包体请求真正携带的数据（如表单内容、上传的文件）
HTTP 返回状态码服务器告诉浏览器「这次请求结果如何」，如 200（成功）、404（找不到）

HTTP 协议头里最需要注意的是请求方式：最常用的是 GET 和 POST 两种。

  • GET：把参数拼在 URL 后面，用来「取」数据（如 ?id=1）。
  • POST：把数据放在包体里，用来「提交」数据（如登录、发文章）。

请求内容主要以 URL 为主，此外还有浏览器版本、主机名等，服务器也会据此做不同处理。

3. 用 http.server 模块构建简单 Web 服务器

Python 内置了一个极简 Web 服务器模块 —— http.server。想发布哪个目录， 就在那个目录里运行：

bash
python3 -m http.server
1

它会把当前目录当作网站根目录，默认监听 8000 端口。

第 100 讲 · 理论盘点：MVC 模型是什么？ ​

本节目标 ​

理解「为什么需要 Web 框架」，掌握 MVC 三层分工，并弄清 Django 的 MTV 与 MVC 的对应关系。

知识要点 ​

1. 没有 Web 框架之前，会遇到什么问题？

手动写 Web 服务端逻辑，通常是这样的流程：用户登录 → 查询数据库 → 返回页面； 匿名用户 → 查询数据库 → 返回另一个页面……大量逻辑重复。由此带来三个麻烦：

问题说明
大量重复逻辑每加一个页面都要重写一遍「连库、拼 HTML」
耦合紧密一处修改可能引发另一处 Bug
依赖关系不清晰代码之间谁依赖谁说不清楚，难维护

2. Web 框架的作用

Web 框架就像盖楼时的结构框架，确保 Web 服务器代码有层次、松耦合、不累赘。

常见的 Web 框架分为 MVC 和 MTV 两种模式，它们的本质相同。

3. MVC 模型是什么

MVC 把 Web 后端代码分成三个层次：

层全称职责
MModel 模型层实现业务对象和数据库对象之间的映射（用 Python 类描述一张表）
VView 视图层负责业务逻辑和用户交互（收到请求要做的主逻辑）
CController 控制层实现用户请求到视图层的调用（决定「哪个 URL 找哪个视图」）

4. Django 的 MTV 与 MVC 的区别

Python 最知名的框架 Django 实现了 MTV 模型。它与 MVC 在定义上不同，但在 解耦和依赖解决方面采用相同的处理逻辑：

Django（MTV）对应 MVC 的哪一层说明
M：Model 模型层Model同上，对象与数据库的映射
T：Template 页面模板相当于 View（展示部分）负责「页面长什么样」，HTML 模板
V：View 视图层相当于 Controller（控制部分）负责接收请求、处理逻辑、选用模板

Django 的数据处理顺序：

用户请求 → URL 控制器 → view 视图 → [Model 模型] → Template 模板 → 返回 HTML
1

📌 记忆要点：MVC 与 MTV 只是「叫法」和「切分位置」不同，目标都是「分层 + 松耦合」。

第 102 讲 · 如何使用 Django-admin 实现文章上传？ ​

本节目标 ​

为 Blog 定义文章模型，把它注册到 admin 后台，并通过后台界面上传（录入）文章数据； 同时学会用 list_display 优化后台列表的显示字段。

知识要点 ​

1. 文章对象模型应当包含哪些字段

按课程 PPT：文章模型应包含 文章标题、文章类别、文章作者、发布时间、文章内容。 字段类型参考官方文档：https://docs.djangoproject.com/zh-hans/4.0/ref/models/fields/

Django 字段类型用途
CharField(max_length=200)短文本（标题、作者）
TextField()长文本（正文内容）
DateTimeField()日期时间（发布时间）
verbose_name="文章标题"给字段起一个中文别名，后台会显示这个别名

⚠️ 切记要把 model 注册到管理后台，否则模型不会出现在后台界面里。

2. 从管理后台上传数据

管理界面地址：http://127.0.0.1/admin（课程里实际用的是 http://127.0.0.1:8080/admin/）。 登录后即可在后台对文章进行「增 / 删 / 改 / 查」——这就是「上传文章」。

3. 优化显示字段

后台列表页默认不显示全部字段，通过一个继承 admin.ModelAdmin 的类来指定：

python
class blogAdmin(admin.ModelAdmin):
    list_display = (字段名称,)

# 注册管理类到管理界面：
admin.site.register(blog, blogAdmin)

第 103 讲 · 如何使用 Django 实现文章发布？ ​

本节目标 ​

把数据库里的文章展示到网页上：做模板（Templates）→ 写视图（View）→ 配 URL → 刷新页面看到文章列表。

知识要点 ​

1. 制作模板

  • 模板放在应用的 templates 文件夹里，用 HTML 展示给用户。
  • 模板除内容外，还能承载**样式（CSS）**以及 JS 等前端脚本实现的逻辑。
  • Django 模板有自己的语法：{% %} 是标签（逻辑），{{ }} 是变量（取值）。

2. 修改视图

  • 根据上一讲创建的 Blog 模型，创建展示用的视图：从数据库取出文章 → 交给模板渲染。
  • ⚠️ 创建视图后，必须修改 urls.py，把用户请求的 URL 映射到指定的视图，否则页面 404。

3. 刷新与重启

  • 以开发模式运行 Django（runserver）：改完代码刷新浏览器就能看到最新页面。
  • 以生产模式运行：需要重启 Django 进程才能生效。

代码实操 ​

本章小结 ​

速查表

主题关键点
Web 客户端 / 服务端客户端 = 浏览器（交互 + 展示）；服务端 = 处理请求、查库、返回数据
HTTP 三样数据协议头（含 GET/POST 请求方式）、包体、状态码
起静态服务器python3 -m http.server [端口]（Python 内置 http.server）
Web 框架作用让代码有层次、松耦合、不累赘；MVC 与 MTV 本质相同
MVCModel（对象↔数据库）/ View（逻辑+交互）/ Controller（请求→视图）
Django MTVModel（同 MVC）、Template（页面）、View（≈ 控制器）
Django 四件套URL 处理、视图、模型、模板
建项目 / 建应用django-admin startproject X；python3 manage.py startapp Y
注册应用在 settings.py 的 INSTALLED_APPS 里加 'Y'
模型迁移改 models.py → makemigrations → migrate
注册后台admin.py 里 admin.site.register(Model, ModelAdmin)
优化后台列表list_display = ("字段名",)
视图渲染render(request, '模板.html', context)
路由映射path('前缀/', include('app.urls')) + path('', views.index)
起服务python3 manage.py runserver [IP:端口]

三句话

  1. 客户端管展示、服务端管处理——一切 Web 开发都从这条分工出发。
  2. Django 用 MTV 分层：模型管数据、模板管页面、视图管逻辑，URL 负责把请求接进来。
  3. 跑通 Blog 就四步：建项目应用 → 写 model 并迁移 → 注册 admin 传数据 → 写 view+template 展示。
