第 111 讲 · 聚焦异同：物联网与互联网有啥不一样？ ​

本节目标 ​

用两个差异（连接方式、性能）说清物联网和传统互联网到底不一样在哪。

知识要点 ​

1. 连接方式的差异：从「人-机交互」到「机-机交互」

  • 传统互联网体现的是 人-机交互：人负责输入（打字、点按）和接收机器输出（屏幕、声音），机器负责计算。
  • 物联网结构下，设备自己也能产生数据、接收数据——也就是说设备本身也完成了输入输出。

物联网设备主要分两类：

类型作用例子
传感器类（产生数据 / 输入）接收来自外界的数据温度传感器、位置传感器、激光雷达、相机
执行器类（接收数据 / 输出）接收用户指令，完成特定动作马达、机械臂、舵机

2. 性能的差异：终端弱，服务器强

  • 传统互联网里，服务器的性能通常都比个人终端强，处理能力强劲。
  • 物联网终端设备性能有限（芯片小、内存小、耗电受限），往往需要 边缘设备（边缘计算服务器）或中心服务器配合，把数据传上去集中处理。

💡 一句话记法：互联网是「人 ↔ 机器」，物联网是「人 ↔ 机器 ↔ 设备」， 设备既是数据的来源，也是指令的归宿；而设备太弱，算力得「外包」给云。

第 112 讲 · 理论盘点：基础但不简单的 TCP 协议 ​

本节目标 ​

理解为什么物联网常用 TCP，看懂 TCP 的通信过程，并用 Python socket 亲手跑通一次完整通信。

知识要点 ​

1. 物联网通信为何常用 TCP 协议

  • TCP 比 HTTP 更简洁：在轻量级设备上占用更少资源、消耗更低带宽。 （HTTP 是建立在 TCP 之上的「应用层协议」，用它要额外带一堆请求头 / 状态码，对单片机是负担。）
  • TCP 是可靠协议：能确保设备真的执行了用户的指令。
  • 有时为了更轻量，会采用 UDP + 自行编写校验来实现可靠通信（自己造一个更省内存的「TCP」）。

2. TCP 协议概述

TCP（传输控制协议）是面向连接的：通信前要先「建立连接」，就像打电话要先拨号接通。

text
客户端                          服务端
  │        ① SYN（我要连你）
  │  ─────────────────────────►
  │        ② SYN + ACK（收到，我也连你）
  │  ◄─────────────────────────
  │        ③ ACK（确认，连接建立）
  │  ─────────────────────────►
  │                              ← 这一步叫「三次握手」
  │  ───── 数据收发（可靠、有序）─────►
  │        ④ FIN / ACK（挥手断开）
  │  ◄─────────────────────────►

  • 三次握手：建立连接要来回三次，双方都确认「对方在、我要连」才继续。
  • 可靠：每个数据包都要被确认，丢了会重传，所以「指令一定送到」。
  • 有序：数据按发送顺序到达，不会乱序。

📌 记住：TCP 是物联网通信最常用的协议。掌握它的通信过程，你才能写出更高效的设备控制程序。

代码实操 ​

下面这个脚本把「服务端」和「客户端」放进同一个文件：用 threading 在后台线程起服务端， 主线程当客户端，一次 python3 就能看到完整通信过程，跑完自动关闭、不会常驻。

对应文件：code/112-tcp-demo.py（完整代码如下）。

python
#!/usr/bin/env python3
# -*- coding: utf-8 -*-
"""
第 112 讲 · TCP 协议演示：一个脚本里同时跑「服务端」和「客户端」。

场景：模拟物联网里的一台「温度传感器节点」（服务端）与一部「手机」
（客户端）通过 TCP 通信——手机问「现在几度？」，节点把温度读数回给它。

💡 为什么服务端和客户端写在一个文件里？
   真实物联网里，服务端和客户端是两块板子（或两台机器），要开两个终端分别运行。
   为了让文档里一条命令就能看到完整通信过程，这里用 threading 在后台线程里
   起服务端，主线程当客户端。脚本跑完会自动关闭，**不会常驻、不会卡住**。

运行：  python3 112-tcp-demo.py
"""
import socket
import threading
import time

HOST = "127.0.0.1"   # 回环地址：等价于「自己跟自己通信」，不依赖真实网络
PORT = 65432         # 端口号，取 >1024 的值可避免权限问题

# 模拟温度传感器的「连续读数」：每被问一次，就吐出一个新温度
READINGS = [25.3, 25.5, 25.4, 25.8, 26.1]


def sensor_server() -> None:
    """温度传感器节点（服务端）：监听端口，收到请求就回一个温度。"""
    with socket.socket(socket.AF_INET, socket.SOCK_STREAM) as srv:
        # 端口复用：脚本反复运行时，避免「Address already in use」
        srv.setsockopt(socket.SOL_SOCKET, socket.SO_REUSEADDR, 1)
        srv.bind((HOST, PORT))
        srv.listen()
        print(f"[传感器节点] 已启动，监听 {HOST}:{PORT}")

        # 一共只服务 len(READINGS) 次请求，然后退出
        for temp in READINGS:
            conn, addr = srv.accept()          # 阻塞，等客户端来连
            with conn:
                request = conn.recv(1024)      # 收客户端发来的请求
                print(f"[传感器节点] 收到来自 {addr[0]}:{addr[1]} 的请求：{request!r}")
                reply = str(temp).encode()     # 组装回复（bytes）
                conn.sendall(reply)            # 发回去
                print(f"[传感器节点] 已回复温度：{reply.decode()} °C")


def phone_client() -> None:
    """手机客户端：连上节点，发请求，打印收到的温度。"""
    time.sleep(0.3)                            # 等后台线程把服务端先起来
    for i in range(len(READINGS)):
        with socket.socket(socket.AF_INET, socket.SOCK_STREAM) as cli:
            cli.connect((HOST, PORT))          # 发起 TCP 连接（三次握手）
            cli.sendall(b"TEMP?")              # 发请求：字符串要 encode 成 bytes
            data = cli.recv(1024)              # 等回复
            print(f"[手机] 第 {i + 1} 次查询 → 收到 {data.decode()} °C")
            time.sleep(0.2)                    # 稍等，让日志顺序更好读


def main() -> None:
    # 后台线程起服务端
    server = threading.Thread(target=sensor_server, name="sensor-server")
    server.start()

    # 主线程当客户端，连上去问 5 次
    phone_client()

    server.join()                              # 等服务端线程收尾
    print("通信结束：服务端与客户端均已关闭（脚本未常驻）。")


if __name__ == "__main__":
    main()

    srv.listen()

        print("已连接：", addr)
        while True:
            data = conn.recv(1024)
            if not data:
                break
            print("收到：", data)
            conn.sendall(b"echo: " + data)   # 原样回显

第 113 讲 · 理论盘点：物模型与模组 ​

本节目标 ​

搞懂物模型（用数据描述设备）和模组（芯片 + 周边硬件的封装）这两个物联网核心概念。

知识要点 ​

1. 怎样通过物模型定义智能设备

物模型是「把设备抽象成数据的模板」——它不关心设备长什么样，只关心它有哪些数据、能做什么事。 （这和我们学过的 Django Template 思路异曲同工：都是「模板 + 填充」。）

物模型包含 三类内容：

种类含义举例（以智能风扇为例）
属性（Property）设备「现在是什么状态」（可读可写的数据）当前档位、是否开机、风速
事件（Event）设备运行过程中产生的信息或故障过热告警、电机堵转
方法 / 动作（Method / Action）设备执行的某个动作（下发指令）开机、关机、调到 3 档、摇头

为了体现扩展性，物模型一般采用 JSON 格式定义（谁都能读写，加字段不影响老系统）。

2. 像搭积木一样掌握模组

  • 物联网芯片负责设备通信和 IO 接口的管理。
  • 为了便于使用，通常把芯片和周边硬件（天线、晶振、Flash、电源管理…）组合成一个模组。
  • 好处：不必从零开发——买一块模组就是「搭好的一块积木」，直接写代码即可。

💡 类比：物模型是「说明书/表格」（这台设备能干嘛），模组是「现成的积木块」（硬件封装好）， 两个合起来，才能既统一描述、又快速落地。

代码实操 ​

第 114 讲 · 如何为 ESP32 安装 MicroPython？ ​

本节目标 ​

认识 ESP32-DevKitC 开发板，知道 MicroPython 是什么，并掌握把它烧录进 ESP32 的完整流程。

知识要点 ​

1. ESP32 开发板简介

  • 为便于验证，课程使用外设丰富的 ESP32-DevKitC 开发板做模组选型。
  • ESP32 有 4MB Flash 存储空间，支持 WiFi、蓝牙等常见通信方式。
    • Flash = 板子上的「硬盘」，断电不丢数据，烧进去的 MicroPython 固件和你写的代码都放这儿。

2. 安装 MicroPython

  • MicroPython 是专门为硬件开发实现的 Python 版本。

第 115 讲 · 怎样通过 MQTT 协议构建消息队列？ ​

本节目标 ​

理解消息队列在物联网中的作用，搞懂 MQTT 的「发布/订阅」模型，并看懂发布者与订阅者代码。

知识要点 ​

1. 消息队列在物联网开发中的用途

  • 队列机制为设备并发提供了有效的缓存：设备一多、消息一涌，先用队列存起来，慢慢处理，不丢不乱。
  • 消息队列使用生产者-消费者设计模式，两大角色是 订阅者（Subscriber） 和 发布者（Publisher）：
    • 发布者：往某个「主题（Topic）」发消息（如：温度节点把 25.3 发到 foo_topic）。
    • 订阅者：订阅这个主题，一有新消息就被回调处理（如：手机 App 收到温度就显示）。
角色干什么类比
发布者 Publisher往主题里「发」消息广播电台
订阅者 Subscriber订阅主题，「收」消息打开收音机听某个频道
主题 Topic消息的分类频道电台频率，如 foo_topic

2. 使用消息队列实现数据通信

  • 物联网中经常用 MQTT 协议实现消息队列。
  • 目前 MQTT 协议最新版本为 5.0，典型的 EMQX、HBMQTT 等都能完整支持。
  • 消息队列服务器除了保证消息及时、稳定，还在 MQTT 协议基础上提供 QoS、权限验证等基础服务。
    • QoS（服务质量）：0 = 最多一次，1 = 至少一次，2 = 恰好一次——按可靠性需求选。

💡 为什么用「队列」而不是让设备直接点对点连？因为设备数量多、并发高，队列做缓冲 + 的发布订阅做解耦， 发布者不需要知道谁在听，订阅者也不需要知道谁发的，系统才好扩展。

课后作业 ​

把本章 code/esp32/ 里的文件对照注释再读一遍，尝试改一个参数（比如把上报周期从 sleep(2) 改成 sleep(5)）， 想想改完之后，OLED 刷新和手机收到的频率会怎么变。

参考答案：sleep(2) 改成 sleep(5) 后，主循环每 5 秒才读一次温度、刷一次屏、发一次 MQTT， 于是 OLED 上的数字更新变慢，手机 App 收到的温度消息也变为每 5 秒一条。 周期越长越省电，但实时性越差——这正是物联网设备「功耗 vs 时效」的经典权衡。

速查表

主题关键点
物联网 vs 互联网设备能产生/接收数据；终端弱、靠边缘或中心服务器集中处理
TCP面向连接、可靠、有序；三次握手建立连接；物联网最常用
socket 通信服务端 bind → listen → accept；客户端 connect；数据用 bytes
物模型设备的数据模板（JSON）：属性 / 事件 / 方法（=动作）
模组芯片 + 周边硬件的封装，拿来即用，不必从零开发
MicroPython硬件版 Python；烧固件到 ESP32 的 Flash
烧录esptool.py --chip esp32 --port <串口> --baud 460800 write_flash -z 0x1000 <固件.bin>
MQTT消息队列 + 发布/订阅；服务器（EMQX）提供 QoS、权限验证
DHT11温湿度传感器；湿度 ±5%RH、温度 ±2°C；d.measure() → d.temperature()
SSD1306OLED 驱动；SoftI2C 接线，oled.text() / oled.show() 显示
接线安全温感引脚 VCC / GND 切勿反接，否则可能损坏元件

三句话

  1. 物联网 = 互联网 + 设备端：设备既是数据来源也是指令归宿，弱算力交给服务器。
  2. TCP 是可靠的电话、MQTT 是发布订阅的广播：一个保证「送到」，一个解决「多设备并发」。
  3. 物模型描述「是什么」，模组提供「怎么做」：概念 + 硬件 + 网络三者合力，才是一台完整设备。
