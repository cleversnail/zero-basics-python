第 77 讲 · 扩展数据类型：怎样使用更复杂的数据类型？ ​

本节目标 ​

学会用 collections 模块里的四种「扩展数据类型」，在普通列表、字典、元组不够用时补上短板。

知识要点 ​

collections 是 Python 标准库，提供了一批比内置类型更「专用」的容器：

类型作用相对内置类型的增强
namedtuple（命名元组）每个位置都有名字的元组既能像元组那样按下标取，又能像对象那样按名字取
deque（双端队列）两端都能进出的队列比 list 多了 appendleft() / popleft()
Counter（计数器）统计元素出现次数一键得到 most_common() 排行榜
UserDict / UserList字典 / 列表的「子类化」基类继承它就能给字典、列表加自定义规则

1. 命名元组 namedtuple

namedtuple() 是一个工厂函数：你告诉它「叫什么名字、有哪些字段」，它返回一个新的类。

python
from collections import namedtuple
Point = namedtuple('Point', ['x', 'y'])
p1 = Point(11, y=22)
1
2
3

它的好处是：p1.x 和 p1[0] 都能取到同一个值，既清晰又兼容元组的用法。

2. 双端队列 deque

普通列表在头部插入/删除很慢（要挪动全部元素），deque 专门解决这个问题：

  • append() / pop()：从右端进出
  • appendleft() / popleft()：从左端进出

3. 计数器 Counter

把任意可迭代对象（字符串、列表都行）丢进去，它就统计出每个元素出现了几次，most_common(n) 直接给前 n 名。

4. 字典 / 列表子类化

当你需要「一个有点特殊行为的字典」，不要从 dict 继承，而是继承 UserDict。它内部用 self.data 持有真正的字典，重写 __setitem__、__getitem__ 等方法就能定制行为。

第 78 讲 · 魔术方法：怎样通过类构造自己需要的数据类型？ ​

本节目标 ​

理解什么是魔术方法，并学会通过重写它们，让自定义对象支持 +、-、len()、下标取值等操作。

知识要点 ​

1. 什么是魔术方法

魔术方法是 Python 预先定义好、有特定功能的一类方法，名字前后各有两个下划线，例如 __init__。 你可以把它理解为数据类型的接口：Python 在执行 a + b 时，其实是在调用 a.__add__(b)。

2. 基本数据类型里也有魔术方法

我们平时写的 dict1['a']，本质上就是 dict1.__getitem__('a')：

python
dict1 = {'a': 1}
dict1['a']            # 结果为 1
dict1.__getitem__('a')  # 结果也是 1
1
2
3

用 dir(对象) 可以把一个对象身上的魔术方法全部列出来。如果你想改变「取字典值」的过程， 就重写 __getitem__()。

3. 类的常用魔术方法

魔术方法触发时机
__new__()创建对象时（比 __init__ 更早）
__init__()初始化对象时
__call__()把对象当函数调用 obj() 时
__del__()对象被回收时
__add__() / __sub__()执行 + / - 时
__getitem__()执行 obj[i] 时
__len__()执行 len(obj) 时
__repr__()print(obj) 时显示什么

💡 一句话记住：想改哪个行为，就重写哪个魔术方法。

class MyDict(dict):

        else:
            super().__setitem__(key, value)

语言优点缺点

第 80 讲 · 怎样将已有算法改造成符合项目的特定算法？ ​

本节目标 ​

学会用大 O 复杂度评估算法优劣，并用 functools.lru_cache 把「又慢又对」的算法改造成「又快又对」。

知识要点 ​

1. 为什么要掌握算法

  • 掌握成熟软件的设计思想
  • 能正确评估自己的代码质量（而不是凭感觉说「挺快的」）

2. 评估算法：大 O 复杂度

用「大 O 表示法」描述算法随数据量增长的大致耗时。常见几种，从快到慢：

复杂度含义典型例子
O(1)常数时间数组按下标取值、字典查 key
O(log n)对数时间二分查找
O(n)线性时间遍历一遍列表
O(n²)平方时间双层循环两两比较
O(2ⁿ)指数时间朴素递归斐波那契

3. 改造算法：给斐波那契数列加缓存

用朴素递归算斐波那契，复杂度是 O(2ⁿ)——因为同样的子问题被反复算了很多遍。 如果把「算过的结果」存起来，下次直接取，复杂度立刻降到 O(n)。这就是 LRU（Least Recently Used， 最近最少使用）思想的轻量应用，Python 已经内置好了：

  • functools.lru_cache()：函数缓存装饰器（可指定缓存上限）
  • functools.cache()：Python 3.9+ 的简写，等价于 lru_cache(maxsize=None)

第 81 讲 · 设计模式：怎样合理组合多个函数和类？ ​

本节目标 ​

认识设计模式的三大分类（创建型、结构型、行为型），并动手实现单例、单态、适配器三种模式。

知识要点 ​

设计模式按「解决什么问题」分为三大类：

类别解决什么典型模式
创建型对象的「创建」方式单例模式、单态模式
结构型类与对象的「组合」方式适配器模式
行为型对象之间的「职责分配」责任链模式

1. 单例模式（Singleton）

整个程序里某个类只有一个实例。Python 最省事的实现方式是「靠 import」—— 因为一个模块在同一个进程里只会被导入（执行）一次，所以模块级变量天生就是唯一的。

2. 单态模式（Monostate）

单例要求「只有一个对象」，单态则允许创建多个对象，但让它们共享同一份数据。 实现窍门：把数据存在类属性上，而不是实例属性上。

3. 适配器模式（Adapter）

用来解决接口不兼容的问题：把一个类的接口「转接」成调用者期望的接口。 中文名里的「转接头」——TypeC 的接口转成 TypeA 能插的样子。

4. 责任链模式（Chain of Responsibility）

发送者和接收者解耦：请求沿着一条链传递，直到有对象处理它。 经典场景是异常的分层处理——用户请求网站失败时，从 DNS → HTTP → Socket 逐层向上返回。

第 84 讲 · 计算资源充足时，如何通过并行设计提高效率？ ​

本节目标 ​

分清「并发」与「并行」，并会用 concurrent.futures 的线程池（ThreadPoolExecutor）并发执行任务。

知识要点 ​

1. 并发 vs 并行

并发（Concurrency）并行（Parallelism）
定义宏观上多个任务同时在执行同一时刻真的在同时发生
CPU一个核心交替运行多个程序多个核心同时处理多个程序

一句话：并发是「看起来同时」，并行是「真的同时」。

2. concurrent.futures 库

concurrent.futures 里的 Executor 是「并行任务」的抽象类，它能用线程和进程两种方式实现并行：

  • ThreadPoolExecutor（线程池）：用线程实现并发，适合 I/O 密集型任务（下载、读写文件等）
  • ProcessPoolExecutor（进程池）：用多核 CPU，适合 计算密集型任务

提交任务用 submit()，它返回一个 future（「未来的结果」）：

python
executor.submit(函数, 参数...)
1

用 concurrent.futures.as_completed(...) 可以「谁先做完就先处理谁」。

1. 进程与线程的差别

任务类型推荐模型原因

计算密集型多进程每个进程有独立的 GIL，能真正跑满多核

2. 进程池 Pool

with Pool(10) as p:

1
2
3

Pool(10) 表示开 10 个进程，map 会把第二个参数里的每一项分给进程去算。

3. 进程通信：为什么需要它？

多个进程各有各的内存，变量无法直接共享，所以要用操作系统提供的机制交换数据：

方式用法特点
队列 Queueq.put() 写、q.get() 读先进先出，最常用

python
from multiprocessing import Process, Queue

def producer(q, n):
    for i in range(1, n + 1):
        q.put(i)
    q.put(None)

def consumer(q):
    hits = []
    while True:
        item = q.get()
        if item is None:
            break
        if item % 7 == 0:
            hits.append(item)
    print(f"1~10000 中能被 7 整除的数共 {len(hits)} 个，前 5 个：{hits[:5]}")

if __name__ == '__main__':
    q = Queue()
    p1 = Process(target=producer, args=(q, 10000))
    p2 = Process(target=consumer, args=(q,))
    p1.start(); p2.start(); p1.join(); p2.join()

设计模式创建型（单例/单态）、结构型（适配器）、行为型（责任链）
Redis键值型 NoSQL，pip3 install redis，conn.set/get
MySQL关系型数据库，pip3 install PyMySQL，改完记得 commit()
并行ThreadPoolExecutor 适合 I/O，ProcessPoolExecutor 适合计算
多进程通信Queue（队列）、Pipe（管道）、shared_memory（共享内存）；if __name__ == '__main__' 是标配

三句话

  1. 内置类型不够用，先翻 collections，再考虑用魔术方法自己造一个。
  2. 算法慢，先用大 O 找出瓶颈；能缓存就缓存（lru_cache），往往一行代码见效。
  3. 需要并发，分清 I/O 密集（用线程）和计算密集（用进程）；跨进程交换数据要用队列或管道。
